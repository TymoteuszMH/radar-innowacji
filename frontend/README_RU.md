# Innovation Radar v0.5 — Online Discovery + Core Engine

**Назначение:** конкурсный прототип HackNation 2026 / „Radar innowacji” для обнаружения, предварительной оценки и сопоставления идей с потребностями организаций. Интерфейс на польском, в направлении **Gov.pl-inspired Institutional UI**; это не официальный сервис Gov.pl.

## Запуск

1. Распакуйте архив так, чтобы получилась папка `InnovationRadar`.
2. Откройте `InnovationRadar/app/index.html` в Chrome или Edge.
3. Сервер, npm и API-ключи **не нужны**. Интернет потребуется только для живого поиска через OpenAlex; офлайн-режим сохраняется.

В прототипе есть 10 синтетических инноваций, 6 синтетических потребностей и 7 синтетических организаций. Они **не являются реальными организациями или подтверждёнными партнёрами**.

## Главное новое в v0.5: поиск онлайн

1. Откройте `app/index.html` и раздел **Szukaj w internecie**.
2. Введите запрос на польском или английском, например `edukacja` или `adaptive learning`.
3. Выберите **OpenAlex API na żywo** для реального интернет-поиска или **NCBR — lokalna próbka** для поиска по трём заранее проверенным реальным проектам из польского каталога.
4. Откройте первоисточник, просмотрите предварительную оценку и совпадения. Нажмите **Sprawdź i dodaj do katalogu**, дополните пропущенные поля и только затем сохраните.
5. При ошибке подключения OpenAlex система сообщает о проблеме; NCBR и документы остаются доступны офлайн.

**Различайте типы данных:** OpenAlex — *живой API* (запросы из браузера), NCBR — *фиксированная локальная выборка* из трёх официальных страниц gov.pl на 21 ноября 2026 года, а стартовые организации остаются **синтетическими**.

**Технический статус:** в среде создания проекта нет доступа к внешним API. Запросы OpenAlex, парсинг результата, обработка ошибки и интерфейс проверены на мокированных HTTP-ответах в формате OpenAlex. Реальный сетевой запрос в вашем браузере необходимо проверить отдельно; на `file://` доступ может блокироваться CORS или политикой API. Никаких ключей в клиентском JavaScript нет.

**Оценки:** научные публикации не считаются подтверждёнными инновациями. Отсутствующие данные не придумываются. Для OpenAlex часто потребуется вручную уточнить проблему, стадию разработки, эффект и условия внедрения. Дедупликация работает по DOI и нормализованному заголовку в пределах текущей выдачи; это не глобальный поиск дублей.

## Основная функциональность v0.4 (сохранена)

В левом меню появился раздел **Wykrywanie w dokumentach**.

- Загрузите до 15 файлов **TXT, MD, текстовых PDF** (до 10 МБ каждый) или вставьте текст.
- Нажмите **Wykryj kandydatów**. Система локально ищет описания с заголовками *Tytuł / Problem / Rozwiązanie*; поддерживает несколько идей в одном файле, если они разделены такими заголовками.
- Для каждого кандидата показывает извлечённые сведения, **цитаты и номера строк**, предварительную оценку, похожие записи, подходящие потребности и действия для проверки.
- Откройте блоки **Ocena i ograniczenia**, **Dopasowania i następne kroki**, **Cytaty źródłowe**, чтобы проверить выводы.
- Нажмите **Sprawdź pola i dodaj do katalogu**. После этого откроется **обычная форма**, где необходимо подтвердить поля и организацию. **Без этой операции ничего не записывается.**
- На первой странице Discovery есть кнопка **Uruchom 2 przykłady**, показывающая два синтетических примера без выбора файлов.

Для проверки реального пути PDF можно использовать файлы из `demo_documents/` (образовательная инновация и маршруты вывоза отходов). Там же лежат `.txt`-версии на случай, если конкретный PDF не прочитается.

### Честные ограничения Core Engine

**Это работающий детерминированный офлайн-движок, не LLM и не поиск в интернете.**

- `discovery.js` распознаёт явные заголовки и подсказывает словарные теги. Сложные свободные тексты без заголовков могут быть пропущены.
- `evidence.js` связывает извлечённое поле с цитатой в локальном документе. **Это доказывает присутствие фразы в источнике, а не истинность её содержания.**
- `assessment.js` рассчитывает предварительные оценки. Оценка качества доказательств 0 может означать, что сам текст явно указывает на отсутствие измерений или независимой проверки. Это не отрицательный научный результат.
- `matching.js` использует лексическое сходство, теги, ключевые слова и ограничения по готовности. Баллы — **эвристический рейтинг соответствия**, а не вероятность успеха, проверенная новизна или согласие организации.
- `actions.js` предлагает план действий, который должен утвердить человек.
- OCR нет: сканированные PDF могут не распознаваться.
- Не используйте персональные или конфиденциальные документы. Автономность не заменяет промышленной защиты данных.

## Как безопасно обновить v0.3

1. **Сначала сделайте копию старой папки InnovationRadar.** Если есть собственные записи, нажмите **Eksport JSON** в приложении.
2. Замените **файлы приложения** из новой версии (`app/index.html`, `app/app.js`, `app/style.css`, `app/core/` и при необходимости тесты/документацию). Можно также распаковать архив в **отдельный каталог** и открыть его для проверки.
3. **Не удаляйте и не перезаписывайте `InnovationRadar/data/workspace.json`.** В архиве этого пользовательского файла нет.
4. Повторно выберите папку через **Pliki i zapis lokalny → Wybierz folder** при необходимости.
5. Откройте каталог и проверьте сохранённые записи.

Формат хранения остаётся `innovation-radar-local-backup` **version 2**; миграция пользовательского хранилища не требуется. Новый движок сохраняет только дополнительные необязательные поля для записи, созданной через Discovery.

### Локальные данные

По умолчанию собственные записи хранятся в `localStorage` браузера. В Chrome/Edge при наличии поддержки File System Access API приложение позволяет выбрать корневую папку `InnovationRadar` и сохранять записи в `data/workspace.json`. Доступ к папке может потребоваться предоставить повторно при новой сессии.

**JSON-экспорт остаётся обязательной резервной копией**, особенно при работе через `file://` или с разными профилями браузера.

## Архитектура

```text
InnovationRadar/
├── app/
│   ├── index.html               ← открыть двойным щелчком
│   ├── style.css
│   ├── app.js                   ← UI и навигация
│   ├── data/seed.js            ← синтетические данные
│   └── core/
│       ├── discovery.js        ← пакетное обнаружение кандидатов [v0.4]
│       ├── evidence.js         ← проверка сохранности цитат [v0.4]
│       ├── assessment.js       ← оценка и ссылки на источники
│       ├── matching.js         ← прямой/обратный поиск и ограничения
│       ├── actions.js          ← план последующих шагов
│       ├── analysis.js         ← старый простой импорт одного текста
│       ├── pdf.js              ← офлайн чтение части текстовых PDF
│       ├── store.js            ← совместимый workspace v2
│       ├── localApi.js         ← локальный адаптер без сетевых запросов
│       ├── onlineSearch.js     ← поиск, нормализация, объединение
│       └── sources/
│           ├── openalex.js     ← живой OpenAlex REST API
│           └── ncbr.js         ← снимок 3 проверенных польских проектов
├── demo_documents/            ← 2 PDF и 2 TXT с тестовыми идеями
├── tests/
└── README_RU.md
```

**Принцип Asset Factory:** обычные теги `<script defer>` с `window.Radar...`, без сборщика, Node.js или сервера для самого приложения. Новые движковые файлы выделены по функциям, а не превращены в отдельные сервисы.

## Тесты разработчика

Node.js 20+ требуется **только для тестов**, не для приложения. Из корня папки выполните:

```bash
node tests/core.test.cjs
node tests/engine.test.cjs
node tests/ui.test.cjs
node tests/folder.test.cjs
```

В этой версии проведены модульные тесты существующей логики и Core Engine, а также тест Chromium с двумя демонстрациями, созданием карточки, сохранением цитат, обратным поиском, загрузкой двух PDF, проверкой мобильной компоновки и отсутствия ошибок JavaScript. **Прямое `file://` в тестовом браузере заблокировано политикой его окружения**; пользовательское подтверждение локального запуска v0.3 не является автоматической проверкой v0.4. Выполните этот дополнительный шаг на собственном компьютере.
